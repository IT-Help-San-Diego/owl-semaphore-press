# owl-semaphore-press

The [Owl Semaphore](https://github.com/IT-Help-San-Diego/owl-semaphore)
publication toolchain, extracted into a reusable package so sibling
repositories (e.g. calibration-scope FINDINGS reports) render artifacts
inside the **same integrity regime** as the specification PDFs:

- the **codified design language** — state colors, letter-spaced labels,
  per-page owl headers, the page-one machine-readable **banner tuple**,
  title page with DOI block, contact sheet, and the classification-ledger
  back page (`document.build_typst_document`);
- the **four canonical states** as importable constants (`states`);
- the markdown → pandoc → Typst → PDF pipeline (`pipeline.render_pdf`);
- **Zenodo release automation** implementing the reserve-DOI-first
  convention from owl-semaphore's RELEASE-PROCESS.md (`zenodo`, `owl-press`).

## Fidelity guarantee

`build_typst_document` is a faithful extraction of the template that produced
the owl-semaphore v3.0.0 release PDFs. `tests/test_parity_owl_semaphore.py`
proves it: given the same inputs, the package emits **byte-identical** Typst
source to the legacy `generate_pdfs.py`. Run it against a local owl-semaphore
checkout:

```bash
OWL_SEMAPHORE_REPO=../owl-semaphore python3 -m unittest discover -s tests -v
```

## Provenance stamping

Every rendered artifact records the renderer identity + version in its
first-line comment (`generated by owl-semaphore-press X.Y.Z`) — the same way
a paper reports its instrument model. **Consumers must pin the package
version** (e.g. `owl-semaphore-press==0.1.0`); a styling change must never
silently restyle an already-released artifact.

## Install

```bash
pip install "owl-semaphore-press[render] @ git+https://github.com/IT-Help-San-Diego/owl-semaphore-press"
```

The `render` extra pulls `typst` and `pikepdf`; `pandoc` must be on PATH.
The Zenodo CLI is pure stdlib and needs no extras.

## Rendering (library)

```python
from owl_semaphore_press import PressConfig, render_pdf, states

cfg = PressConfig(
    release_label="v1.0.0",
    author="Carey James Balboa",
    orcid="0009-0000-5237-9065",
    repo_url="github.com/IT-Help-San-Diego/calibration-scope",
    version_doi="10.5281/zenodo.XXXXXXX",     # reserved via owl-press
    concept_doi="10.5281/zenodo.YYYYYYY",
    previous_version=("v0.9.0", "10.5281/zenodo.ZZZZZZZ"),
)

doc = {
    "md": "FINDINGS.md",
    "pdf": "FINDINGS.pdf",
    "badge": "assets/releases/540/META-composite-transparent-540.png",
    "contact_sheet": "assets/proofs/OWL-SEMAPHORE-MASTER-PROOF.png",
    "color": states.METACOGNITIVE.color,
    "color_rgb": states.METACOGNITIVE.color_rgb,
    "label": states.METACOGNITIVE.label,
    "state_token": states.METACOGNITIVE.token,
    "title": "Calibration Scope — Findings",
    "subtitle_typst": "Findings Report — Metacognitive Classification",
    "mathline": states.METACOGNITIVE.mathline,
    "quote": states.METACOGNITIVE.quote,
    "standard_ref": states.METACOGNITIVE.standard_ref,
    "contact_caption": "Calibration Scope — Findings",
    "pdf_subject": "Calibration Scope findings report (v1.0.0)",
}

render_pdf(doc, repo_root=".", cfg=cfg)
```

## Zenodo release flow (CLI)

Implements owl-semaphore's reserve-DOI-first convention: one Zenodo record
per release, DOI embedded in the artifacts before publication, GitHub
auto-ingest side-stepped.

```bash
export ZENODO_TOKEN=...   # scopes: deposit:write deposit:actions

# 1. Create the new-version draft off the concept record's latest deposition
#    and print the reserved version DOI:
owl-press zenodo new-version 20468727

# 2. Embed the reserved DOI in source / rebuild PDFs / tag the release
#    (consumer repo's release process), then:
owl-press zenodo metadata <draft-id> --from .zenodo.json
owl-press zenodo upload   <draft-id> RELEASE-FILES...
owl-press zenodo files    <draft-id>

# 3. Publish — irreversible, so it demands the flag:
owl-press zenodo publish  <draft-id> --yes
```

Use `--sandbox` (with `ZENODO_SANDBOX_TOKEN`) to rehearse the whole flow on
sandbox.zenodo.org before touching the real concept record.

## Relationship to owl-semaphore

owl-semaphore remains the **normative source** of the design language; this
package is the rendering instrument. owl-semaphore's own pipeline switches to
consuming this package at its next version-bumped release (the parity test
makes that switch a no-op for artifact bytes).
